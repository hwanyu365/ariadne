# 창 스펙

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | ariadne 창 (UC5) |
| 작성일 / 최종 수정일 | 2026-11-14 / 2026-11-14 |
| 버전 | 1.0 |
| 기준 커밋 ID | 3c5f8cd |

- **기능명:** 입력·실행·진행 표시·결과 요약·설정 저장
- **목적 (Why):**
  - 같은 사이트의 다음 편을 받을 때마다 셀렉터를 다시 넣지 않는다
  - 수백 페이지 수집이 어디까지 왔는지, 왜 멈췄는지 로그를 거슬러 읽지 않고 안다
  - 문제가 생기는 구조: 화면(렌더러)은 preload 통로만 쓰고 검증·실행은 메인 프로세스가 한다 → 엔진의 로그 줄이 화면 상태의 유일한 원천이다

## 2. 목표 및 범위

### In Scope

- 입력 검증과 입력란 오류 표시
- 수집·probe·요소 선택 실행과 중지, 진행 상태·진행 막대·결과 요약
- 입력값·최근 URL·사이트별 셀렉터 저장
- 창이 포커스를 잃은 동안 끝난 수집의 OS 알림

### Out of Scope

- 수집 동작 자체 → `docs/spec_collect.md`
- 셀렉터 후보 생성 → `docs/spec_selector.md`
- 여러 수집 동시 실행 (색인 제외 범위)

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 사용자로서, 같은 사이트의 다음 편을 바로 받기 위해, 창에서 입력하고 진행을 보며 지난 입력을 이어 쓰기를 원한다 [요구사항] → FR#1~FR#11

### 3.2 기능 요구사항

- `FR#1` 시작 전에 입력을 검사하고, 틀린 입력은 해당 입력란에 표시한다 [as-built] (`NFR#6`)

  ```
  Given  URL 이 비었다
  Then   probe·선택기·수집 모두 거부한다
  Given  수집 대상 또는 next 가 비었다
  Then   수집만 거부하고 probe·선택기는 진행한다
  Given  숫자 칸에 숫자가 아닌 값, 알 수 없는 인코딩
  Then   거부한다
  When   거부된다
  Then   로그와 결과 영역에 사유가 나오고, 그 입력란이 aria-invalid 로 표시되며 포커스가 옮겨진다. 접힌 고급 옵션이면 펼친다
  ```

- `FR#2` 실행 중에는 상태·받은 페이지 수·마지막 파일·걸린 시간·진행 막대를 보인다 [as-built] (`NFR#6`)

  ```
  When   수집을 시작한다
  Then   상태가 '수집 중' 이 되고 페이지 로그 줄마다 페이지 수와 파일명이 갱신된다
  Given  최대 페이지 N
  Then   진행 막대가 받은 수 / N 을 보인다
  Given  최대 페이지 0
  Then   진행 막대는 진행 중임만 보인다
  ```

- `FR#3` 실행은 한 번에 하나이고, 창이 사라지면 실행도 멈춘다 [as-built] (`NFR#6`)

  ```
  Given  실행 중
  When   다시 시작을 누른다
  Then   진행 중인 실행의 로그·상태를 지우지 않는다
  Given  실행 중인 창을 닫는다
  Then   수집이 멈추고, 다음 창에서 새 실행을 시작할 수 있다
  ```

- `FR#4` 끝나면 결과를 로그 위에 한 줄로 요약하고, 받은 파일이 있으면 폴더 열기를 둔다 [as-built] (`NFR#6`)

  ```
  When   수집이 끝난다
  Then   완료·실패·중지, 받은 페이지 수, 걸린 시간이 보인다. 완료·실패는 멈춘 사유 한 줄을, 중지는 받은 파일이 남아 있다는 안내를 붙인다
  Then   같은 문구가 항상 렌더링된 알림 영역(role=status)에도 들어간다 → 스크린리더가 읽는다
  Given  엔진이 곧바로 실패해 종료 알림이 시작 응답보다 먼저 온다
  Then   화면이 '실행 중' 으로 굳지 않고 실패로 끝나며 버튼이 되살아난다
  ```

- `FR#5` 로그는 최근 2000줄만 두고, 경고·실패·완료 줄을 색과 줄 앞 표시로 구분한다 [as-built] (`NFR#6`)

  ```
  Given  2000줄을 넘는 로그
  Then   오래된 줄부터 지운다
  Given  '경고·주의·건너뜀' / '실패' / '완료' 로 시작하는 줄
  Then   warn / error / ok 로 분류되고 줄 앞에 '! ' / '× ' / '✓ ' 가 붙는다
  Given  로그·결과 문구에 페이지가 정한 셀렉터·글자가 섞여 온다
  Then   마크업으로 해석하지 않고 글자 그대로 보인다 (`NFR#13`)
  ```

- `FR#6` 첫 실행 전 빈 로그 자리에 첫 수집까지의 단계를 안내한다 [as-built] (`NFR#6`)

  ```
  Given  아직 실행하지 않았다
  Then   안내가 보인다
  When   실행한다
  Then   안내가 사라진다
  ```

- `FR#7` 입력값은 바뀔 때마다 사용자 데이터 폴더의 `settings.json` 에 저장하고 다음 실행에 채운다 [as-built] (`NFR#10`)

  ```
  When   입력값·모드·스위치를 바꾼다
  Then   저장되고, 창을 다시 열면 그 값으로 채워진다
  Given  설정 파일이 없거나 깨졌거나 모르는 키·틀린 타입이 있다
  Then   시작은 실패하지 않고 아는 키만 쓴다
  ```

- `FR#8` 수집을 시작한 URL 을 최근 10개까지, 호스트별 셀렉터 묶음을 최근 50개 호스트까지 남긴다 [as-built] (`NFR#10`)

  ```
  When   수집을 시작한다
  Then   URL 이 최근 목록 맨 앞에 오고(중복 제거), 그 호스트의 수집 대상·next·제목·제외·인코딩·모드가 사이트 설정에 남는다
  Given  URL 을 다른 호스트로 바꾼다
  Then   그 호스트의 사이트 설정으로 입력란과 모드를 채운다
  Given  같은 호스트 안에서 URL 을 바꾼다
  Then   채우지 않는다
  Given  파일의 사이트 설정·최근 목록에 틀린 형태가 섞였다
  Then   맞는 항목만 상한까지 쓴다
  ```

- `FR#9` 수집이 끝났을 때 창이 포커스를 갖고 있지 않으면 OS 알림으로 결과를 알린다 [as-built] (`NFR#16`)

  ```
  Given  창이 포커스를 잃은 채 수집이 끝난다
  Then   '수집 완료/실패/중지' 와 받은 페이지 수로 알린다
  Given  창이 포커스를 갖고 있거나, probe·선택기가 끝난다
  Then   알리지 않는다
  ```

- `FR#10` 화면 창은 앱이 가진 파일만 연다 [as-built]

  ```
  Given  화면 창에서 window.open, 다른 주소로 이동
  Then   새 창이 생기지 않고 화면 문서가 그대로다 → preload 통로를 다른 문서에 내주지 않는다
  ```

- `FR#11` 창 높이는 작업 영역(작업 표시줄 제외) 안에 들어온다 [as-built]

  ```
  Given  작업 영역 높이 H
  Then   창 높이는 min(900, H − 40) 이다
  ```

- `FR#12` 키보드만으로 실행·중지하고 포커스가 항상 보인다 [as-built] (`NFR#6`)

  ```
  When   Ctrl+Enter (macOS ⌘↵)
  Then   수집을 시작한다
  When   실행 중 Esc
  Then   중지한다
  Then   Tab 으로 옮긴 포커스가 눈에 보인다
  ```

- `FR#13` 모든 안내·오류·로그 문구는 경어체다 [as-built] (`NFR#6`)

## 4. 데이터 및 API 스펙

### 4.1 settings.json

| 키 | 형태 | 비고 |
| --- | --- | --- |
| url, sel, next, title, exclude, charset, prefix | 문자열 | 입력란 값 |
| max, start, digits, timeout, delay | 숫자 문자열 | 입력란 값 그대로 |
| mode | text 또는 image | |
| headful, merge | boolean | |
| recent | 문자열[] | 최대 10, 최근 것이 앞 |
| sites | {호스트: {sel, next, title, exclude, charset, mode}} | 최대 50, 최근 것이 뒤 |

- 화면이 보내는 저장 요청은 입력값만 바꾼다 → recent·sites 는 수집 시작 때만 바뀐다

### 4.2 IPC

| 채널 | 방향 | 내용 |
| --- | --- | --- |
| run:start | 화면 → 메인 | {kind, values, mode, headful, merge} → {error, field} |
| run:log | 메인 → 화면 | {text, level, progress} |
| run:pick | 메인 → 화면 | {key, sel, line} (화면은 key·sel 만 쓴다) |
| run:done | 메인 → 화면 | {stopped} |

- 로그 분류: 줄 머리 `완료` ok / `실패` error / `경고`·`주의`·`건너뜀` warn / `중단` info
- 진행: `[{n}] … -> {파일}` 줄에서 읽는다 → 화면용 이벤트를 따로 두지 않는다

## 6. 동작 로직 및 정책

### 6.1 실행 상태 [FR#2, FR#3, FR#4]

```
대기 ─시작→ 실행 중 ─거부→ 입력 확인
             ├─ 실패 줄 있음 → 실패
             ├─ 중지 → 중지됨
             └─ 그 밖 → 완료
```

- 화면은 시작 응답을 기다리기 전에 실행 상태로 바꾸고, 거부될 때만 되돌린다 → 즉시 실패가 시작 응답보다 먼저 와도 상태가 굳지 않는다

### 6.2 설계 결정

| 결정 | 선택 | 기각한 대안 | 근거 |
| --- | --- | --- | --- |
| `D#1` | 진행 상태를 엔진 로그 줄에서 읽는다 | 화면용 진행 이벤트 | 로그와 상태가 어긋나지 않는다 |
| `D#2` | 설정을 바뀔 때마다(300ms 모아서) 저장한다 | 종료 시 저장 | 비정상 종료에도 입력이 남는다 |
| `D#3` | URL 을 쿼리까지 저장한다 | 쿼리 제거 | 연재물은 쿼리가 편·페이지를 가리킨다. 로그인 페이지는 제외 범위라 토큰 URL 은 대상이 아니다 |
| `D#4` | 사이트 설정은 호스트가 바뀔 때만 채운다 | URL 이 바뀔 때마다 | 같은 사이트에서 고쳐 쓰던 셀렉터를 덮지 않는다 |
| `D#5` | 로그 줄은 낭독하지 않고 상태·결과만 알림 영역으로 전한다 | 로그를 live region 으로 | 수백 줄이 쏟아질 때 낭독이 밀린다 |
