# 셀렉터 찾기 스펙

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | ariadne 셀렉터 찾기 (UC3·UC4) |
| 작성일 / 최종 수정일 | 2026-11-14 / 2026-11-14 |
| 버전 | 1.1 |
| 기준 커밋 ID | 1cd7b71 |

- **기능명:** probe(후보 목록)와 요소 선택기(화면에서 클릭)
- **목적 (Why):**
  - 셀렉터가 틀리면 1페이지만 받고 끝난다 → 수집 실패의 대부분이 셀렉터에서 난다
  - probe 는 후보를 목록으로, 선택기는 가리킨 요소에서 후보를 만든다 → 두 방법 모두 "다음 페이지에서도 맞는 셀렉터" 를 고르게 하는 것이 목적이라 한 파일에 둔다
  - 문제가 생기는 구조: 선택기는 원격 페이지 위에 UI 를 얹는다 → 페이지 동작을 바꾸거나 페이지 스크립트가 가짜 선택을 보낼 수 있다

## 2. 목표 및 범위

### In Scope

- probe: 인코딩, 입력한 셀렉터의 매치 수·미리보기, next·본문·이미지 후보, iframe 경고
- 선택기: 클릭한 요소의 셀렉터 후보와 매치 수, 대상(본문/이미지·next·제목·제외) 전환, 입력란 채우기

### Out of Scope

- iframe 안의 요소 선택 (색인 제외 범위)
- 셀렉터 자동 확정 → 사람이 매치 수를 보고 고른다

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` 셀렉터를 모르는 사용자로서, 수집이 1페이지에서 끝나지 않게 하기 위해, 페이지의 셀렉터 후보를 목록으로 보기를 원한다 [요구사항] → FR#1~FR#3
- `US#2` 사용자로서, 후보 목록을 화면과 대조하지 않기 위해, 화면에서 요소를 클릭해 셀렉터를 얻기를 원한다 [요구사항] → FR#4~FR#7

### 3.2 기능 요구사항

- `FR#1` probe 는 입력한 셀렉터마다 매치 수와 미리보기를, 그리고 next·본문·이미지 후보와 iframe 존재를 보여 준다 [as-built] (`NFR#8`)

  ```
  Given  URL 과 (선택) 수집 대상·next·제목·제외 셀렉터
  When   probe 를 누른다
  Then   셀렉터마다 'n개 매치' 와 앞 3개 미리보기가 로그에 나온다
  Then   next 후보(다음·next·›·» 등 글자), 본문 후보(200자 초과, 짧은 순), 이미지 후보(큰 이미지가 많은 컨테이너 순)가 나온다
  Given  페이지에 iframe 이 있다
  Then   개수와 주소를 보이고, 그 안의 본문은 수집할 수 없다고 알린다
  Given  셀렉터를 비워 둔다
  Then   입력 오류 없이 후보만 보여 준다
  ```

- `FR#2` probe 는 읽은 인코딩을 항상 보여 주고 오판이면 경고한다 [as-built] (`NFR#9`)

  ```
  When   probe 를 누른다
  Then   '인코딩: {이름}' 줄이 나온다
  Given  선언 없는 UTF-8 을 다른 인코딩으로 읽었다
  Then   수집과 같은 경고가 나온다
  ```

- `FR#3` probe 의 미리보기는 수집과 같은 제외를 거친다 [as-built] (`NFR#14`)

  ```
  Given  텍스트 모드, 제외 셀렉터
  Then   수집 대상 미리보기에 제외 요소의 글자가 없다
  Given  제외가 수집 대상을 가린다
  Then   경고를 남긴다
  ```

- `FR#4` 선택기는 클릭한 요소의 셀렉터 후보를 매치 수와 함께 제시한다 [as-built] (`NFR#8`, `D#4`)

  ```
  Given  id 가 있는 요소(이미지 제외)를 클릭한다
  Then   '#id' 가 첫 후보다
  Given  클래스가 여럿인 요소
  Then   전체 클래스 후보와 첫 클래스만 쓴 짧은 후보를 함께 내고, 후보마다 매치 수(1개면 ✓, 아니면 ⚠)를 보인다
  Given  이미지를 클릭한다
  Then   컨테이너 + img 후보가 첫 후보다: id 가 있는 가장 가까운 조상이면 '#id img', 없으면 클래스가 있는 가장 가까운 조상이면 'tag.클래스 img', 둘 다 없으면 'img'
  Then   이미지 자신의 id·클래스 후보는 그 뒤에 낸다
  Then   입력란에는 첫 후보가 채워진다 → 이미지를 클릭하면 컨테이너 후보가 채워진다
  Then   선택기 자신의 툴바·하이라이트는 매치 수에 들지 않는다
  ```

- `FR#5` 선택기는 페이지 동작을 바꾸지 않고 문서마다 다시 선다 [as-built] (`NFR#7`)

  ```
  Given  링크를 클릭한다
  Then   이동하지 않고 선택으로만 처리한다
  Given  툴바의 대상 버튼·위치 버튼을 누른다
  Then   대상이 바뀌거나 툴바가 옮겨지고, 그 클릭은 선택으로 세지 않는다
  Given  리디렉션·새로고침으로 문서가 바뀐다
  Then   선택기가 다시 선다
  Given  iframe 문서
  Then   선택기를 세우지 않는다
  ```

- `FR#6` 선택 통로는 preload 격리 world 에만 있고, 그 선택기 창에서 사람이 누른 클릭만 받는다 [as-built] (`NFR#13`)

  ```
  Given  페이지 스크립트
  Then   선택 통로와 후보 함수가 보이지 않는다
  Given  페이지가 합성한 click() (선택·완료 버튼 포함)
  Then   선택·완료로 세지 않는다
  Given  선택기 창이 둘이다
  Then   한 창의 선택·완료가 다른 창의 콜백으로 가지 않는다
  ```

- `FR#7` 선택한 셀렉터는 형태를 검사한 뒤 대상에 맞는 입력란에 채운다 [as-built] (`NFR#13`)

  ```
  Given  대상 본문·이미지 / next / 제목 / 제외
  Then   수집 대상 / next / 제목 / 제외 입력란에 채우고 후보 목록을 로그에 남긴다
  Given  모르는 대상(객체 원형의 이름 포함), 빈 셀렉터, 문자열이 아닌 값
  Then   버린다
  Given  후보 목록 일부가 깨졌다
  Then   맞는 후보만 로그에 남긴다
  ```

### 3.3 비기능 요구사항

- 색인 공통 제약 `NFR#7`, `NFR#8`, `NFR#9`, `NFR#13`, `NFR#14` 를 따른다

## 4. 데이터 및 API 스펙

- `probe(url, sel, nextSel, options)` → 결과는 로그로만 낸다. 창을 띄웠으면 사용자가 중지할 때까지 기다린다
- `pick(url, onPick, options)` → 완료·중지·창 닫기 중 먼저 오는 것에서 끝난다

| 선택 페이로드 필드 | 형태 | 비고 |
| --- | --- | --- |
| target | 대상 이름 | 텍스트 모드: 본문·next·제목·제외, 이미지 모드: 이미지·next·제목 |
| sel | 비지 않은 문자열 | 첫 후보 또는 사용자가 고른 후보 |
| candidates | {sel, n}[] | 로그 표시용. 형태가 맞는 것만 쓴다 |
| text | 문자열 | 클릭한 요소의 글자 또는 src. 메인 프로세스는 쓰지 않는다 |

## 6. 동작 로직 및 정책

### 6.1 설계 결정

| 결정 | 선택 | 기각한 대안 | 근거 |
| --- | --- | --- | --- |
| `D#1` | 선택기는 preload 격리 world 에 넣는다 | 페이지 main world 주입 | main world 면 페이지 스크립트가 통로를 불러 가짜 선택을 보낸다 |
| `D#2` | 툴바·하이라이트는 fixed 로 띄우고 표식 속성으로 매치에서 뺀다 | 문서 흐름에 삽입 | 레이아웃을 밀면 고르려는 요소의 위치가 바뀐다 |
| `D#3` | 후보 생성 함수와 선택기를 한 스크립트로 세운다 | 따로 주입 | 하나만 실패하면 클릭 핸들러가 조용히 죽는다 |
| `D#4` | 이미지 후보는 id 조상 → 클래스 조상 → `img` 순으로 하나를 골라 첫 후보로 둔다 | 이미지 자신의 id·클래스를 첫 후보로 둠 / 바로 위 부모만 봄 / 조상마다 후보를 모두 냄 | 첫 후보가 입력란에 채워진다 → 한 장짜리면 페이지마다 1장만 받는다. 바로 위 부모는 id·클래스가 없는 래퍼(`p`·`span`)인 경우가 흔하다. 조상마다 내면 후보가 길어져 매치 수 대조가 어려워진다. id 는 클래스보다 상태 값이 섞이지 않아 다음 페이지에서도 맞는다 |
