- **프로젝트:** 페이지네이션으로 이어지는 웹 페이지를 끝까지 넘기며 본문 텍스트와 이미지를 로컬 파일로 받아 두는 데스크톱 도구
- **목적 (Why):**
  - 연재물처럼 한 편이 여러 페이지로 나뉜 글·이미지를 사람이 next 를 수백 번 누르지 않고 받는다
  - 셀렉터 한 번만 맞추면 같은 사이트의 다음 편도 같은 설정으로 받는다
  - 성숙도 `poc` → 스펙은 목적·범위와 유스케이스 색인까지만 적는다 (`CLAUDE.md` 성숙도 표)

## 비즈니스 규칙

- `BR#1` 수집 대상 사이트의 이용약관과 robots 정책을 어기는 사용은 사용자 책임이다. 도구는 우회 수단(차단 회피, 인증 우회)을 제공하지 않는다.
- `BR#2` 받은 파일은 로컬에만 둔다. 도구는 어디로도 업로드하지 않는다.

## 공통 제약

여러 기능에 걸친 제약과 기능 사이 모순은 여기에 모은다.

- `NFR#1` next 를 누른 뒤 수집 대상이 실제로 바뀔 때까지 기다린 다음 다음 페이지로 본다. URL 이 바뀌지 않는 SPA 도 같은 판정으로 넘긴다.
  - 바뀐 값은 잠시 뒤 다시 읽어 같을 때만 확정한다 → 본문이 그려지는 도중의 값을 저장하지 않는다.
  - 이미 받은 페이지와 주소·수집 대상이 모두 같은 페이지가 다시 나오면 멈춘다 → 마지막 페이지의 next 가 처음으로 돌아가는 사이트에서 끝없이 받지 않는다.
    - 주소가 다르면 본문이 같아도 계속 받는다 → 삽화·공지처럼 같은 본문의 회차에서 멈추지 않는다. 주소가 그대로인 SPA 는 수집 대상만으로 본다.
  - next 가 새 탭으로 여는 링크이거나 누를 수 없는 링크면 그 주소로 같은 탭에서 넘어간다. 셀렉터가 링크 안쪽 장식 요소를 가리켜도 감싼 링크의 주소를 쓴다. 버튼·입력 요소를 감싼 링크는 다음 페이지가 아닐 수 있어 쓰지 않는다.
- `NFR#2` 멈출 때는 왜 멈췄는지(셀렉터 불일치 / 마지막 페이지 / 이미 받은 페이지 / 타임아웃 / 사용자 중지)를 로그에 남긴다.
  - next 로 받은 새 문서가 HTTP 오류이고 수집 대상이 없으면 상태 코드를 사유에 붙인다 → 차단·서버 오류가 타임아웃으로 보이지 않게 한다.
  - 저장을 마친 마지막 페이지의 주소와 번호를 남긴다 → 그 주소와 번호로 다시 시작하면 그 페이지부터 다시 받아 이어진다.
  - 일시적 오류도 재시도하지 않는다 → 사유만 정확히 남긴다 (`BR#1`).
- `NFR#3` 페이지 하나를 받으면 즉시 파일로 쓴다. 중간에 끊겨도 그때까지 받은 것은 남는다.
- `NFR#4` 파일명은 `{접두사}_{페이지번호}` 로 시작하고 번호 자릿수와 시작 번호를 지정할 수 있다. 이미지는 뒤에 `_{장번호}` 가 붙는다.
  - 첫 파일 이름이 이미 있으면 경고를 남기고 덮어쓴다 → 이어 받기와 재수집을 막지 않되 이전 결과가 지워지는 것을 알린다.
- `NFR#5` 이미지 한 장을 못 받아도 그 페이지의 나머지와 다음 페이지는 계속 받는다.
  - 응답이 이미지가 아니면(핫링크 차단 HTML 등) 건너뜀으로 남긴다. 확장자는 받은 내용으로 정하고, 못 정하면 주소·응답 형식으로 정한다.
  - 지연 로딩 주소 속성(`data-src`, `data-original`, `data-lazy-src`)을 `src` 보다 먼저 본다. 한 페이지 안의 같은 주소는 한 번만 받는다.
  - 지연 이미지를 채우려는 스크롤이 끝나지 않아도 경고만 남기고 계속한다.
- `NFR#6` UI 는 수집 중에도 응답하고, 중지 요청은 현재 페이지를 마친 뒤 반영한다.
  - 다음 페이지를 기다리는 중이나 페이지 간 대기 중에 누른 중지는 그 자리에서 반영한다 → 페이지를 하나 더 받지 않는다.
  - 진행 상태(페이지 수·마지막 파일)는 엔진의 페이지 로그 줄에서 읽는다 → 화면용 이벤트를 따로 두지 않아 로그와 상태가 어긋나지 않는다.
  - 경고·실패 로그는 색으로 구분한다 → `NFR#9` 경고가 수백 줄 사이에 묻히지 않게 한다.
- `NFR#7` 선택기는 페이지의 동작을 바꾸지 않는다 → 클릭을 가로채 링크 이동을 막고, 레이아웃을 밀어내지 않으며, 자신의 요소는 선택 대상과 매치 수에서 제외한다.
- `NFR#8` 셀렉터는 후보 여러 개를 매치 수와 함께 제시한다. 상태 클래스가 섞여 다음 페이지에서 깨질 셀렉터를 고르기 전에 드러나야 한다.
- `NFR#9` 페이지 인코딩은 브라우저 추정에 맡기되, 틀린 추정이 조용히 지나가지 않게 한다.
  - charset 선언이 없는 UTF-8 페이지를 Chromium 은 기본 인코딩으로 읽는다 → 수집은 깨진 채 성공한다.
    - 앱 내장 Chromium 의 기본 인코딩은 OS 로캘과 무관하게 windows-1252 다. 그래도 판정은 아래처럼 기본값에 기대지 않는다.
  - 메인 문서의 원래 바이트가 비ASCII 를 담은 올바른 UTF-8 인데 브라우저가 UTF-8 이 아닌 인코딩으로 읽었으면 probe 와 텍스트 수집 로그에 경고한다. probe 는 읽은 인코딩을 항상 보여 준다.
    - 브라우저가 고른 인코딩 이름으로는 판정하지 않는다 → 기본 인코딩이 바뀌면 놓친다.
    - 선언이 없는 경우, 선언이 틀린 경우, 지정이 틀린 경우를 같은 규칙으로 잡는다.
  - 사용자가 인코딩을 지정하면 메인 문서 응답의 charset 을 그 값으로 바꿔 추정과 페이지의 선언을 건너뛴다. 수집·probe·선택기 모두 같다.
  - iframe 문서는 바꾸지 않는다 → 인코딩이 다른 광고·임베드가 깨지지 않게 한다.
  - 2xx 가 아닌 응답과 새 탭(`target=_blank`)은 대상이 아니다 → 수집은 원래 탭의 정상 응답만 읽는다.
  - 알 수 없는 인코딩 이름은 시작 전에 거부한다. 판정은 브라우저와 같은 이름 표(WHATWG Encoding)로 한다 → 통과한 이름을 브라우저가 무시하는 경우가 없다.
- `NFR#10` 창의 입력값은 바뀔 때마다 OS 사용자 데이터 폴더의 `ariadne/settings.json` 에 저장하고 다음 실행에 채운다.
  - Windows `%APPDATA%`, macOS `~/Library/Application Support`, Linux `~/.config`.
  - 바뀔 때마다 저장한다 → 앱이 비정상 종료돼도 입력이 남는다.
  - 파일이 없거나 깨졌거나 모르는 키가 있어도 시작은 실패하지 않는다 → 아는 키만 쓰고 나머지는 기본값이다.
  - 저장은 로컬에만 한다 (`BR#2`).
  - URL 은 쿼리까지 그대로 저장한다 → 연재물 URL 은 쿼리가 편·페이지를 가리켜, 지우면 이어 쓰기가 성립하지 않는다. 로그인이 필요한 페이지는 제외 범위라 인증 토큰이 실린 URL 은 대상이 아니다.
- `NFR#11` 수집·probe·선택기는 앱에 내장된 Chromium(Electron)으로 띄운다. 외부 브라우저를 찾거나 요구하지 않는다.
  - 세 OS 가 같은 엔진으로 돈다 → `NFR#9` 판정과 페이지 순회가 OS 마다 달라지지 않는다.
  - 실행마다 비영속 세션을 새로 만든다 → 쿠키가 다음 실행으로 넘어가지 않는다.
- `NFR#12` 배포는 `v*` 태그 push 로 만든 GitHub Release 에 OS 별 실행 파일을 첨부해 한다.
  - Windows x64 portable exe, macOS Apple Silicon zip(.app), Linux x64 AppImage. 모두 설치 없이 실행한다.
  - 세 OS 빌드가 모두 성공해야 Release 를 만든다 → 일부 OS 만 빠진 Release 가 남지 않는다.
  - 코드 서명은 하지 않는다 → 처음 실행할 때 Windows SmartScreen·macOS Gatekeeper 경고가 뜬다.

- `NFR#13` 수집 창의 원격 페이지는 앱과 사용자 PC 에 닿지 못한다.
  - 새 창(`target=_blank`, `window.open`)을 만들지 않는다 → 수집은 원래 탭만 읽는다.
  - 권한(알림·위치·미디어 등) 요청과 다운로드를 거부한다 → 수집에 필요 없다.
  - 이미지·next 주소는 웹 주소(http·https)이거나 지금 페이지와 같은 스킴일 때만 따라간다 → 원격 페이지가 로컬 파일을 받게 하거나 그쪽으로 넘기지 못한다.
  - 선택기의 선택 통로는 preload 격리 world 에만 있고, 그 창이 보낸 것이며 사람이 누른 클릭일 때만 받는다 → 페이지 스크립트가 가짜 선택·완료를 보내지 못한다.
  - 선택기가 보낸 셀렉터·텍스트는 페이지가 정한 값이다 → 형태를 검사한 뒤 입력란의 값으로만 쓴다.

## 제외 범위

- 로그인·캡차·결제가 필요한 페이지
- iframe 안의 본문 (probe 가 iframe 존재만 알린다)
- 받은 파일의 후처리 (ePub·PDF 변환, 이미지 합치기)
- 예약 실행·대기열·동시 수집
- 명령줄(CLI) 실행
