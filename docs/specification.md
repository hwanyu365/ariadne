- **프로젝트:** 페이지네이션으로 이어지는 웹 페이지를 끝까지 넘기며 본문 텍스트와 이미지를 로컬 파일로 받아 두는 데스크톱 도구
- **목적 (Why):**
  - 연재물처럼 한 편이 여러 페이지로 나뉜 글·이미지를 사람이 next 를 수백 번 누르지 않고 받는다
  - 셀렉터 한 번만 맞추면 같은 사이트의 다음 편도 같은 설정으로 받는다
  - 성숙도 `poc` → 스펙은 목적·범위와 유스케이스 색인까지만 적는다 (`CLAUDE.md` 성숙도 표)

## 비즈니스 규칙

- `BR#1` 수집 대상 사이트의 이용약관과 robots 정책을 어기는 사용은 사용자 책임이다. 도구는 우회 수단(차단 회피, 인증 우회)을 제공하지 않는다.
- `BR#2` 받은 파일은 로컬에만 둔다. 도구는 어디로도 업로드하지 않는다.

## 공통 제약

여러 기능에 걸친 제약과 기능 사이 모순은 여기에 모은다.

- `NFR#1` next 를 누른 뒤 수집 대상이 실제로 바뀔 때까지 기다린 다음 다음 페이지로 본다. URL 이 바뀌지 않는 SPA 도 같은 판정으로 넘긴다.
- `NFR#2` 멈출 때는 왜 멈췄는지(셀렉터 불일치 / 마지막 페이지 / 타임아웃 / 사용자 중지)를 로그에 남긴다.
- `NFR#3` 페이지 하나를 받으면 즉시 파일로 쓴다. 중간에 끊겨도 그때까지 받은 것은 남는다.
- `NFR#4` 파일명은 `{접두사}_{페이지번호}` 로 시작하고 번호 자릿수와 시작 번호를 지정할 수 있다. 이미지는 뒤에 `_{장번호}` 가 붙는다.
- `NFR#5` 이미지 한 장을 못 받아도 그 페이지의 나머지와 다음 페이지는 계속 받는다.
- `NFR#6` UI 는 수집 중에도 응답하고, 중지 요청은 현재 페이지를 마친 뒤 반영한다.
  - 진행 상태(페이지 수·마지막 파일)는 코어의 페이지 로그 줄에서 읽는다 → 창과 CLI 가 같은 코어를 그대로 쓴다.
  - 경고·실패 로그는 색으로 구분한다 → `NFR#9` 경고가 수백 줄 사이에 묻히지 않게 한다.
- `NFR#7` 선택기는 페이지의 동작을 바꾸지 않는다 → 클릭을 가로채 링크 이동을 막고, 레이아웃을 밀어내지 않으며, 자신의 요소는 선택 대상과 매치 수에서 제외한다.
- `NFR#8` 셀렉터는 후보 여러 개를 매치 수와 함께 제시한다. 상태 클래스가 섞여 다음 페이지에서 깨질 셀렉터를 고르기 전에 드러나야 한다.
- `NFR#9` 페이지 인코딩은 브라우저 추정에 맡기되, 틀린 추정이 조용히 지나가지 않게 한다.
  - charset 선언이 없는 UTF-8 페이지를 Chromium 은 기본 인코딩으로 읽는다 → 수집은 깨진 채 성공한다.
    - 기본 인코딩은 창 모드·OS 로캘에 따라 다르다 (e.g. headless windows-1252, 한국어 Windows 의 headful EUC-KR).
  - 메인 문서의 원래 바이트가 비ASCII 를 담은 올바른 UTF-8 인데 브라우저가 UTF-8 이 아닌 인코딩으로 읽었으면 probe 와 텍스트 수집 로그에 경고한다. probe 는 읽은 인코딩을 항상 보여 준다.
    - 브라우저가 고른 인코딩 이름으로는 판정하지 않는다 → 기본 인코딩이 바뀌면 놓친다.
    - 선언이 없는 경우, 선언이 틀린 경우, 지정이 틀렸거나 브라우저가 모르는 이름이라 무시된 경우를 같은 규칙으로 잡는다.
  - 사용자가 인코딩을 지정하면 메인 문서 응답의 charset 을 그 값으로 바꿔 추정과 페이지의 선언을 건너뛴다. 수집·probe·선택기 모두 같다.
  - iframe 문서는 바꾸지 않는다 → 인코딩이 다른 광고·임베드가 깨지지 않게 한다.
  - 2xx 가 아닌 응답과 새 탭(`target=_blank`)은 대상이 아니다 → 수집은 원래 탭의 정상 응답만 읽는다.
  - 알 수 없는 인코딩 이름은 시작 전에 거부한다.
- `NFR#10` 창의 입력값은 종료할 때 사용자 설정 폴더(Windows `%APPDATA%/ariadne/settings.json`)에 저장하고 다음 실행에 채운다.
  - 파일이 없거나 깨졌거나 모르는 키가 있어도 시작은 실패하지 않는다 → 아는 키만 쓰고 나머지는 기본값이다.
  - 저장은 로컬에만 한다 (`BR#2`).
  - URL 은 쿼리까지 그대로 저장한다 → 연재물 URL 은 쿼리가 편·페이지를 가리켜, 지우면 이어 쓰기가 성립하지 않는다. 로그인이 필요한 페이지는 제외 범위라 인증 토큰이 실린 URL 은 대상이 아니다.
- `NFR#11` 브라우저는 Playwright 용 Chromium 을 먼저 쓰고, 띄우지 못하면 시스템 Microsoft Edge(`channel="msedge"`)로 띄운다. 수집·probe·선택기 모두 같다.
  - 배포용 exe 는 Chromium 을 싣지 않는다 → 약 150MB 를 덜고 단일 파일로 둔다. Windows 10·11 은 Edge 가 기본 탑재다.
  - 둘 다 실패하면 두 사유와 해결 방법(Edge 설치 또는 `playwright install chromium`)을 담아 실패한다 → 창 로그에 그대로 뜬다.
  - Edge 도 Chromium 엔진이라 `NFR#9` 인코딩 판정은 그대로다.
- `NFR#12` 배포는 `v*` 태그 push 로 만든 GitHub Release 에 `ariadne.exe` 를 첨부해 한다. 코드 서명은 하지 않는다 → 처음 실행할 때 SmartScreen 경고가 뜬다.

## 제외 범위

- 로그인·캡차·결제가 필요한 페이지
- iframe 안의 본문 (probe 가 iframe 존재만 알린다)
- 받은 파일의 후처리 (ePub·PDF 변환, 이미지 합치기)
- 예약 실행·대기열·동시 수집
